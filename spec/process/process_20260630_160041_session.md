## Problem Statement

The DDO Red Team currently writes each finding's `category` field as ad-hoc free text (e.g. `"Missing Evidence"`, `"Style"`). These categories drift between runs and across personas, preventing reliable aggregation or cross-reference by the downstream Interview and Refine phases. Separately, the v0.0.3 release deprecated two hardcoded patch ops (`append_evidence`, `append_review_log`) and locked their removal for v0.0.4 — they remained in code as a backward-compat shim. This session ran the full `/hyper-architect` phase for v0.0.4 to produce a complete, unambiguous Draft PRD for those two scopes.

## Key Decisions & Rationale

| Decision | Alternatives Considered | Reason Chosen |
|---|---|---|
| Deprecated-op removal included in v0.0.4 | Defer to v0.0.5 or v0.0.6 | Locked v0.0.3 resolve decision (RT-v0.0.3-13) mandated removal here; keeping it would leave two codepaths indefinitely |

| Tests = validate persona AV table structure | Fixture-based ddo-red-team integration tests | Persona files *are* the fixtures; no Python contract changed; structural test is the right scope |
| Minimal tutorial fix in v0.0.4 | Full tutorial refresh in v0.0.4; defer entirely to v0.0.6 | `interview_call.py:61` uses `append_evidence` — it would be a broken code sample after op removal. ## Patterns & Lessons

- **LivingMasterPlan gaps require active reconciliation.** The plan's v0.0.4 section silently omitted the deprecated-op removal even though the v0.0.3 resolve locked the decision. Memory files bridging releases (`project_ddo_v003.md` recording RT-v0.0.3-13) are critical for catching this class of gap.
- **Two-round architect interviews are valuable.** The initial Draft PRD left three design choices at implicit defaults. The second-pass "ask what you feel useful" surfaced the tutorial breakage (`interview_call.py` still *using* a soon-to-be-removed op), which would have been discovered only at implementation time without this pass.
- **Tutorial code samples are not documentation — they are executable code.** The tutorial's prose rows saying "removed in v0.0.4" were cosmetic; the `code_samples/interview_call.py:61` usage was functional and would break after the op was removed. Distinguishing these when scoping tutorial work is important.
- **Cognitive vs. mechanical enforcement is a persistent design axis.** The decision to keep `category` free-text (D1/D2) avoids migration and a second validation codepath, but the tradeoff is that AI drift is possible. The persona-table test and the explicit skill instruction are the mitigations; they were both included in the PRD's success metrics.
