## Key Decisions & Rationale

| Decision | Alternatives Considered | Reason Chosen |
|---|---|---|
| Sentinel placed in `meta.title` | Any other string-typed leaf field | `meta.title` is the most semantically meaningful "missing" field; always a string; visible in rendered output |
| `template: "prd"` (not `scientific_report`) | `scientific_report` template | PRD schema is simpler (no `abstract`, `corresponding_author`); fewer required fields reduces fixture complexity |
| 2 sections, 3 evidence entries | Minimum viable (1 section, 1 entry) | v0.0.3 MiniPRD requires ≥2 sections and ≥3 evidence entries; design future-proofs Phase B and C |
| `ev_orphan_placeholder` as the delete target | A section as the delete target | Evidence delete (not section delete) is what v0.0.3 `_dangling_ref_check` protects; MiniPRD explicitly requires ≥1 unreferenced evidence entry |
| One `set` resolution in interview log | Multiple resolutions | Only one sentinel exists; one patch is the minimum that satisfies the loop test; keeps the fixture simple and auditable |
| `decision: revise` (not `fix`) | `fix`, `patch`, other strings | Matches the byte-verified tutorial reference (`revise` = `set` op pairing); `validate_interview_log` only checks presence, not value, but canonical form is preferred |

## Patterns & Lessons

- **Read the integration test before designing fixtures.** `test_loop.py` calls `apply_patches` directly — it does not call `validate_interview_log`. Knowing this meant the interview log only needed `resolutions[]` to work, not a full validated structure. Reading the reference tutorial output confirmed the canonical top-level format anyway.
- **Validate constraint table before writing.** Listing all invariants (date regex, leaf-scalar type, orphan-warns-not-raises, template name, section count) before designing the YAML prevented multiple revision cycles.
- **The orphan design intent belongs in the fixture itself.** `ev_orphan_placeholder.content` documents why the entry is unreferenced, making the file self-explanatory to any future reader who opens it cold.
- **Plan mode doubles as the HITL review gate.** Presenting the full YAML content in the plan file — with field-by-field annotation — gave the human a structured review surface before any files touched the filesystem. The plan approval IS the artifact sign-off.
