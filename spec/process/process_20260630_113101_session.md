## Approach & Methodology

Spec-driven, following the HACF Resolution Agent state machine defined in
`.agents/skills/hyper-resolve/SKILL.md`: **Phase 1** (high-severity collisions, forced trade-offs, max
2 questions/turn) → **Phase 2** (NFR/determinism defaults, batch-approve) → **Phase 3** (Candidate
Artifact routing) → **Phase 4** (compile SuperPRD + MiniPRDs, archive active specs). The deliberate
sequencing rationale: separate the findings that were *factual corrections* (only one right answer)
from the findings that were *genuine trade-offs* (needing a human cost/risk ruling), so the user was
only asked to decide the latter. Before asking anything, live verification was used to ground the
high-risk findings against the actual tree rather than the Red Team's assumptions.

## Patterns & Lessons

- **Verify before you ask.** The Red Team's two Critical findings (RT-01/RT-02) were state-assumption
  errors, not collisions. Grepping the actual tree downgraded RT-01 from "duplicate-id corruption" to a
  one-line wording fix, and turned the question round into the *two* findings that were genuine
  trade-offs. Resolution quality comes from separating corrections from decisions.
- **Don't ask what has an obvious default.** RT-04/06/09/13/15 were batched into a single
  approve/modify/reject question rather than five separate ones — respecting the skill's ≤2-questions
  pacing without burning the user's attention on conventional choices.
- **Match the repo's proven convention over the generic template.** v0.0.3 compiled to a single
  `SuperPRD_v0.0.X_Name.md` in `spec/compiled/`; the `.agents/schemas/*_Template.md` files are
  deprecated stubs that redirect to `AGENTS.md`. Read the surviving artifacts to learn the real shape.
- **Environment gotcha:** `python` is not on this shell's PATH — `python3` (or `uv run`) is required.
  The CLAUDE.md command examples say `python`; they need a `python3` substitution here.
- **The hypergraph updater only propagates status; it never creates nodes.** New nodes are hand-added
  to `architecture.yml` first, then the updater is run to mark the blast radius `needs_review`.
