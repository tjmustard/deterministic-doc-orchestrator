## Patterns & Lessons

- **HTTPS vs SSH push:** The shell environment in this Claude Code session has no git credential helper configured. SSH is the reliable path for interactive sessions. Set the SSH remote early rather than discovering the issue at push time.
- **Context window resumption:** When a session is summarized mid-skill, the SKILL.md instructions and the prior user approvals are preserved in the summary. Re-reading the relevant docs (CHANGELOG, README) before editing is fast and avoids stale-state edits.
- **Fixture signoff guard in release commits:** Any commit that touches `tests/fixtures/` requires `DDO_FIXTURE_SIGNOFF=1`. When using `git add -A` in `/hyper-publish`, this is easy to forget — the transparency gate should always explicitly flag fixture files and remind about the env var.
- **`[Unreleased]` vs existing version block:** When asked where to place post-implementation docs entries in CHANGELOG, users may prefer appending to the last release block rather than starting `[Unreleased]`. Don't assume `[Unreleased]` is always the right target.
- **Test count in tutorial Prerequisites:** Tutorial Prerequisites sections that assert an exact test count will drift as tests are added. Consider phrasing as "N or more passed" or omitting the count and instead directing users to `uv run pytest -q` with no expected-count assertion.
