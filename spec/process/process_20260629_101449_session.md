## Problem Statement

The Deterministic Document Orchestrator (DDO) v0.0.1 existed as six MiniPRDs in `spec/compiled/` but had no implementation. The backbone — validation gate, build orchestrator, schema/template migration, render skill, ingest skill, and test suite — needed to be built from scratch while preserving the project's zero-hallucination and HITL-gate invariants. Once implemented, the suite had two skipped tests gated on human-generated fixture files: a promoted ingest fixture (`tests/fixtures/ingest_output.yaml`) and a set of golden render baselines. Both required human sign-off to promote, with a pre-commit guard to enforce that requirement.

## Approach & Methodology

The session used HACF's `/hyper-execute` skill to fan out 6 parallel/sequential subagent waves aligned to the MiniPRD dependency graph, followed by a human-in-the-loop closeout phase. The dependency ordering was:

- **Wave 1 (parallel):** `MiniPRD_ValidationGate` and `MiniPRD_SchemaTemplateMigration` — foundational, no cross-dependencies.
- **Wave 2 (sequential):** `MiniPRD_BuildCore` — imports `ddo.validation`, so must follow Wave 1.
- **Wave 3 (parallel):** `MiniPRD_RenderSkill` and `MiniPRD_IngestSkill` — both call into build.py and paths.py, so follow Wave 2.
- **Wave 4 (sequential):** `MiniPRD_TestSuite` — tests everything, so runs last.

After the waves, a human-driven closeout addressed doc drift, fixture guard wiring, golden baseline generation, and an ingest candidate from `PRDs/DDO_PRD.md`.

The final phase used an interactive HITL collaborative authoring loop: the AI drafted each section of a fresh `prd`-schema `document_data.yaml` from `PRDs/` + `spec/compiled/SuperPRD.md`, the human approved each section individually, and only after full approval was the document assembled and promoted as the ingest test fixture.

## Key Decisions & Rationale

| Decision | Alternatives Considered | Reason Chosen |
|---|---|---|
| Dependency-aware waves for subagent fan-out | All 6 simultaneous | `build.py` imports `validate()`; test suite tests all code — races would cause import errors and false failures |
| Per-script `ddo/build.py.lock` (PEP 723) | Project-level `uv.lock` | PEP 723 scripts are hermetically self-contained; `uv run --locked ddo/build.py` locks to the script's own lock file, not a project-level one |
| PDF determinism = extracted text equality; byte-identical via `--timestamp` opt-in | Byte-identical PDF always | PDF metadata (creation timestamp) is non-deterministic by default; mandating `--timestamp` would break normal use; text-layer equality is the meaningful invariant |
| Sentinel scan on parsed string values only, never raw bytes/keys/comments | Scan all file content | Keys and comments can legitimately contain the token string (e.g., schema documentation); only an unfilled VALUE is a violation |
| Fabrication tripwire is advisory/non-blocking | Block on any unverified token | Legitimate document content (e.g., product names) won't appear verbatim in all source texts; blocking would create false positives and require constant whitelisting |
| Rewrite FR-5 prose rather than escaping the sentinel token | Add a special "escape" syntax for the sentinel | Escaping adds parser complexity and version-compatibility risk; the fix (synonym prose) is simpler, more readable, and avoids the parser entirely |
| Collaborative HITL section-by-section authoring | Pre-generate a complete draft for one-shot review | Each section has different source availability; interview-then-draft prevents hallucination by surfacing gaps before content is written |
| Promote fixture only after all sections individually approved | Promote after final-assembly approval only | Per-section gates catch issues earlier and allow targeted re-drafting without rejecting the full document |

## Patterns & Lessons

- **Content filter on migration agents:** When a subagent handles file migration that includes license text, its final report may be blocked. The subagent leaves the files in place but can't report completion. Mitigation: read the residual gaps from the files directly rather than relying on the report; fix inline.

- **Sentinel in documentation prose:** The zero-hallucination sentinel `[[DDO::REQUIRES_INPUT: <reason>]]` is a live token — any occurrence in a parsed string value fails the gate, even in documentation prose that is *describing* the sentinel. Always use synonyms when explaining the mechanism in document content.

- **Per-section HITL authoring beats one-shot draft:** Surfacing source gaps per-section (via interview) before writing prevents the AI from filling unknown fields with plausible but unverifiable content. The upfront interview cost is much lower than post-hoc removal of hallucinated content.

- **Fabrication tripwire as a final sanity check:** Running the tripwire as the last step before promotion (advisory, non-blocking) catches any tokens that slipped through the zero-hallucination constraint during authoring. It's not a gate — it's a reminder that some tokens deserve a human second look.

- **`uv run --locked` vs `uv run` for test portability:** The integration test conftest uses `uv run --locked ddo/build.py` via subprocess. The `--locked` flag requires `ddo/build.py.lock` to exist. Without it, the command silently succeeds but ignores lock enforcement. Always generate the lock file when creating a PEP 723 script.

- **Realpath containment is essential for path safety:** The `assert_within_documents` guard resolves symlinks before asserting containment. A `../` in the slug would escape without the realpath resolution step.
