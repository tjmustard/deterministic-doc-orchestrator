## Problem Statement

The Deterministic Document Orchestrator (DDO) had a Draft PRD for its first milestone (v0.0.1, the "deterministic rendering backbone") and a completed Red Team report flagging 14 execution-resilience gaps (4 Critical, 5 High, 5 Medium). Before any code could be written, those findings needed human-mediated decisions and the specification needed to be compiled into an authoritative SuperPRD plus per-module MiniPRDs that the build phase can execute.

No DDO source code existed yet (`ddo/build.py`, schemas, templates, skills are all still to be written in Phase 2).

## Approach & Methodology

Spec-driven, following the HACF Phase 1 state machine defined in `.agents/skills/hyper-resolve/SKILL.md`. The Resolution Agent mediates between the Red Team report and the human via **forced trade-offs** (binary/multiple-choice framed around cost vs. risk vs. time), pacing at **no more than two questions per turn** using the `AskUserQuestion` tool, then compiles the results. Sequencing rationale: resolve highest-severity/architecture-locking items first (cheap to change pre-schema, expensive after), then NFRs/edge cases grouped with proposed defaults, then the non-deterministic-output routing check, then compilation and mandatory archival.

## Key Decisions & Rationale

| Decision | Alternatives Considered | Reason Chosen |
|---|---|---|
| Namespaced sentinel `[[DDO::REQUIRES_INPUT: …]]`, scan parsed string values only | Keep `[REQUIRES USER INPUT` raw-byte scan; keep token but scan values only | Eliminates false-positives on prose (incl. DDO's own docs) at low cost; tool no longer fails on its own dogfood |
| Slug whitelist + realpath containment assertion within `Documents/` | Minimal slug (lowercase + hyphens) only | Closes path-traversal / illegal-filename / length failures for arbitrary ingested titles; zero residual risk |
| Full hermeticity: `==` pins + committed `uv.lock` + bundled/pinned fonts | Pins+lock but defer fonts; keep as-is | Only option that makes renders reproducible across time *and* machines; honors the "hermetic" tenet |
| "Content-identical PDF" = text-layer extraction equality + named pytest | Drop the metric; keep as untested prose | Makes an otherwise unfalsifiable success metric measurable while keeping byte-equality opt-in via `--timestamp` |
| Advisory fabrication tripwire + (A)/(B) claim split | Human gate alone | Gives the HITL reviewer a concrete "verify these" list and states the extraction-fidelity limitation honestly |
| CLI-authoritative routing; `ddo-render` derives flags from `meta` | Error on `meta`/CLI mismatch | Removes the two-sources-of-truth drift; `build.py` never trusts `meta` for routing |
| Render timeout (30s default) + output-size cap | No guard (single-user) | Prevents a runaway template / multi-GB YAML from hanging or OOMing the in-process orchestrator |
| Gate exposed as importable function (not CLI-only) | CLI-only | Lets the deferred v0.0.2 loop reuse validation without subprocessing |
| Timestamp resolved by a pre-build go/no-go spike; vendored CLI counts as hermetic | Commit to in-process now | Avoids discovering mid-build that `--timestamp` is undeliverable; de-scopes US-003 with a record if no hermetic path exists |

2. **Phase 1:** answer the forced-trade-off questions for the Critical findings (two per turn). Expected: decisions for sentinel scan, path safety, hermeticity, PDF metric.

4. **Phase 3:** confirm the Candidate Artifact routing protocol and the fabrication-tripwire / claim-split decision.
5. **Phase 4:** the agent writes `SuperPRD.md` + six `MiniPRD_*.md` to `spec/compiled/`, then runs `python3 .agents/scripts/archive_specs.py <Feature_Name>`. Expected output: "ARCHIVAL SCRIPT: SUCCESS" with the absolute archive path, and `spec/active/` reset to `.gitkeep` only.

Gotchas / order-dependencies:
- Use `python3`, not `python` (the latter is not found on this host).
- Respect the two-questions-per-turn pacing; the skill is a state machine and skipping phases loses the audit trail.
- `architecture.yml` is *not* produced by this skill — it is initialized later by `/hyper-discover`. MiniPRDs reference node IDs from the SuperPRD's proposed blast-radius set.

## Patterns & Lessons

- **Resolve before reconciling tooling:** reading the actual `.gitignore` mid-phase turned an approximate "fix the ignores" mitigation into a precise track/ignore matrix with a concrete acceptance check (`git status --porcelain` + `git check-ignore`). Verify the real artifact before locking a decision about it.
- **Make every guarantee falsifiable:** the most valuable Red Team contribution was exposing assertions ("hermetic", "content-identical") that had no operational definition or test. Each was either given a definition + named test or honestly de-scoped.
- **Gate unknowns, don't bury them:** the Typst timestamp dependency was converted from an implicit risk into an explicit pre-build go/no-go spike, so a Medium story can't silently become Won't-Have mid-build.
- **HACF is the toolchain, not the subject:** `.agents/memory/activeContext.md` reflects the *framework's* own development sprint, which is stale relative to DDO work — confirming that DDO session state belongs in `spec/`, not in the framework's memory files.
- **Forced trade-offs + approve/modify/reject** kept a 14-finding mediation to a handful of turns without sacrificing the decision record.
